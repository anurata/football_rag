# Jリーグ プレビュー・速報・総括 共同作成スキル (`match-curator`)

このスキルは、Jリーグ公式戦のサイクル（試合前・試合中・試合後）に応じ、
客観的データに基づく**確定事実の提示**と、戦術的着眼点の**分岐選択肢（A/B/C案）**を通じて、
ユーザーとエージェントが対話しながら高品質な戦術レポートを共同策定するための標準対話プロトコルです。

仕様詳細: `docs/operation_cycle.md`

---

## 1. 発動トリガー (When to Use)

### Phase 1: プレビュー共同作成 (KO-72h 〜 KO-1h)
- 「次節のプレビューを作りたい」「スタメン予想と展望を対話で決めたい」
- 「〇〇戦のプレビュー草案を出して」「プレビューの選択肢を提示して」

### Phase 2: リアルタイム速報・アジャスト (試合中 / ハーフタイム)
- 「速報を更新して」「今の状況と勝率・交代予測を出して」
- 「ハーフタイムの分析をして」「後半のアジャスト案を提示して」

### Phase 3: 試合後戦術総括・レビュー (Stage 1 / Stage 2)
- 「試合が終わったので総括をまとめたい」「〇〇戦のレビューを作って」
- 「確定スタッツで振り返りをして」「勝敗の分岐点を選択肢で出して」

---

## 2. フェーズ別 共同作成対話フロー (Interactive Workflow)

### Phase 1: プレビュー共同作成フロー (Pre-Match)

1. **分岐選択肢と事実の取得**:
   ```bash
   python scripts/curate_match_preview.py --home <HOME_ID> --away <AWAY_ID> --date <YYYY-MM-DD> --matchweek <MW> --dump-branches
   ```
2. **ユーザーへの提示フォーマット**:
   - **基本情報・確定スタッツ**: 両チームの直近成績、平均得失点、負傷者/出場停止
   - **分岐選択肢 (2〜3案)**:
     - `lineup_home`: ホームスタメン予想（A: 前節継続固定案 / B: 対策・ターンオーバー案）
     - `lineup_away`: アウェイスタメン予想（A: 前節継続固定案 / B: 対策・ターンオーバー案）
     - `tactical_scenario`: 主導権の所在（A: ハイプレス主導 / B: ロースコア警戒戦 / C: 打ち合いシフト）
     - `matchup_focus`: 勝負の焦点（A: サイドの攻防 / B: 中央セカンドボール）
   - 各案には必ず **【事実】**（根拠スタッツ）と **【推測】**（戦術仮説）を併記する。
3. **ユーザー選択の反映とレポート確定**:
   - ユーザーから選択案（例: 「ホームはA、アウェイはB、展開はAで。〇〇選手の起用法に触れて」）を受け取る。
   - レポートをコンパイルして `exports/{match_id}_preview_curated.md` に保存:
   ```bash
   python scripts/curate_match_preview.py --home <HOME> --away <AWAY> --selections '{"lineup_home":"A","lineup_away":"B","tactical_scenario":"A"}' --insights "ユーザーの考察メモ"
   ```

---

### Phase 2: リアルタイム速報・アジャストフロー (Live Match)

1. **戦況データと予測の取得**:
   ```bash
   python scripts/live_match_forecaster.py --game-id <YAHOO_GAME_ID> --hashtag "#クラブタグ"
   ```
2. **対話出力とアジャスト提示**:
   - 現在スコア、消化時間、直近の重要イベント（シュート、CK、カード）
   - SPAIA公式リアルタイム個人スタッツ
   - 動的ベイズ勝率推移（Home% / Draw% / Away% / 残りxG）
   - 点差・時間帯に応じた推奨交代カード（【事実】スタッツと【状況推測】意図）
3. **ユーザーとの対話**:
   - ユーザーの懸念や質問に対し、事実と推測を厳格に分離して回答。

---

### Phase 3: 試合終了戦術総括フロー (Post-Match Review)

1. **確定事実と総括分岐選択肢の取得**:
   ```bash
   python scripts/curate_match_review.py --match-id <MATCH_ID> --dump-branches
   ```
2. **ユーザーへの提示フォーマット**:
   - **試合結果・確定スタッツ比較**: スコア、シュート数、枠内、possession、xG、走行距離、スプリント
   - **時系列重要イベント**: 得点・警告・交代の事実ログ
   - **総括分岐選択肢 (2〜3案)**:
     - `deciding_factor`: 勝敗の決定打（A: 決定力・決定機クオリティ / B: ブロック守備強度 / C: 後半ベンチワーク）
     - `tactical_evaluation`: 戦術的噛み合わせ（A: ハイプレス vs ビルドアップ / B: サイド局地戦 / C: 中盤セカンドボール）
     - `impact_player`: 殊勲選手評価（A: 攻撃牽引MVP / B: 守備の要MIP）
3. **ユーザー選択の反映と確定版保存**:
   - ユーザーの選定とアナリスト視点を取り込み、確定版総括を `exports/{match_id}_review_curated.md` に出力:
   ```bash
   python scripts/curate_match_review.py --match-id <MATCH_ID> --selections '{"deciding_factor":"A","tactical_evaluation":"B"}' --insights "ユーザーのアナリストメモ"
   ```

---

## 3. 厳格運用ポリシー（Fact/Inference 完全分離）

1. **【事実（Fact）】と【推測（Inference）】の明示的ラベリング**:
   - ピッチ上で起きた数値・公式記録・確定イベントは必ず `【事実】` とする。
   - 戦術的意図、監督の狙い、今後の展望などは必ず `【推測】` とする。
2. **情緒的修飾語の排除（ドライ・ファクトモード）**:
   - 「劇的な」「痛恨の」「神がかった」「ズバッと」などの主観的感情語を使用せず、客観的・構造的言語で記述する。
3. **ファイル並置ルール**:
   - 自動生成版（`_auto.md`）は絶対に上書きしない。
   - 対話により合意・確定したファイルは必ず `_curated.md` のサフィックスを付与して保存する。
